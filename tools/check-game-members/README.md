# check-game-members

Static checks against a real, installed copy of a game, without running it. Every assembly is read
through `System.Reflection.MetadataLoadContext`: metadata only, nothing of the game is loaded or
executed, and nothing of it is copied. Needs the .NET 8 SDK.

```bash
dotnet run --project tools/check-game-members -- <mode> …
```

It has three modes.

## `check`: do an integration's `GameType` lookups resolve?

```bash
dotnet run --project tools/check-game-members -- check "<game>/<Game>_Data/Managed" members.tsv
```

`members.tsv` has one row per lookup your integration makes through `Astra.Sdk.GameType`. Columns
are separated by any run of spaces or tabs; `#` starts a comment:

```
# Type        Member          Kind      ExpectedType
Character     -               type      -
Character     localCharacter  static    object
CharacterData isGrounded      instance  Boolean
```

| Kind | the row checks |
|---|---|
| `type` | the type exists (`GameType.Find(…).Exists`); `Member` and `ExpectedType` are `-` |
| `static` | a static field or property (`GameType.Static<T>`) |
| `instance` | an instance field or property, on the type or a base (`GameType.Member<T>`) |
| `method0` | a parameterless instance method (for code that calls `System.Reflection` itself) |

`ExpectedType` is a short CLR type name (`Boolean`, `Single`, `Int32`, `Vector3`, `GameObject`…)
checked against the member's declared type; `object` accepts any reference type. It prints `PASS` or
`FAIL` per row and exits with 1 when any row fails. Run it again after every game update.

## `dump`: what does a type have?

```bash
dotnet run --project tools/check-game-members -- dump "<game>/<Game>_Data/Managed" CharacterData
```

Lists every field and property of the type (searched in every assembly of the folder) with its
declared type: the material for the next `members.tsv` row.

## `il2cpp`: what does a game lack that a plugin names?

```bash
dotnet run --project tools/check-game-members -- il2cpp <plugin.dll> "<profile>/BepInEx/interop"
```

Lists every reference of an IL2CPP plugin into the game's interop assemblies (generated by BepInEx 6
on the game's first start) that the game does not have, with the plugin's methods that use each one.
A member whose body Il2CppInterop could not restore counts as missing. It exits with 0 only when
nothing is missing. For the foundation, run it on
`src/Astra.BepInEx6.IL2CPP/bin/Release/net6.0/Astra.Unity.dll` and read the result as
[`CONTRIBUTING.md`](../../CONTRIBUTING.md#il2cpp-games-the-stripping-audit) says.

It works on a Mono game's `<Game>_Data/Managed` too (type forwarders such as `netstandard`'s are
followed): run it on a pipeline adapter (`Astra.Urp17.dll`, `Astra.Urp14.dll`, `Astra.Hdrp.dll`)
against every engine line you have a game of, before a release
([`CONTRIBUTING.md`](../../CONTRIBUTING.md#releasing)). An adapter built against one line can name a
member another line moved (`IRasterRenderGraphBuilder.SetRenderAttachment`, moved in Unity 6000.3):
it is listed here as missing in that line's games.
